# Сервис бронирования переговорных

Небольшой сервис бронирования переговорных комнат. Реализация диагностического задания на Symfony.

## Стек и требования к окружению

- PHP 8.4
- Symfony 8.1, Doctrine ORM 3.5
- База данных: SQLite (файл создаётся в `var/`, отдельная СУБД не нужна)

## Как запустить

```bash
# 1. Установить зависимости
composer install

# 2. Создать схему БД
php bin/console doctrine:migrations:migrate

# 3. Загрузить тестовые данные (комнаты и оборудование)
php bin/console doctrine:fixtures:load

# 4. Запустить локальный сервер
symfony serve -d
# либо: php -S 127.0.0.1:8000 -t public
```

## Реализованные бизнес-правила

**Комната.** Название не должно быть пустым; вместимость — положительное число.

**Бронирование.** Комната должна существовать; время начала раньше окончания; количество участников положительное и не больше вместимости комнаты; интервал не пересекается с действующими бронями этой комнаты. Брони, «касающиеся» границами (одна заканчивается ровно в момент начала другой), пересечением не считаются. Отменённые брони время не блокируют.

Не реализовано: отмена брони и получение расписания комнаты (см. «Что не успел»).

## Принятые решения

**Какие основные части выделил.** Сущности `Room`, `Equipment` (связь ManyToMany) и `Booking` (ManyToOne на комнату, статус — enum). Входные данные принимаются через DTO (`CreateRoomRequest`, `CreateBookingRequest`). Бизнес-логика вынесена в сервисы (`RoomService`, `BookingService`), доступ к данным — в репозитории. Нарушения правил выражены доменными исключениями. Контроллеры выступают только как HTTP-граница: принимают запрос, вызывают сервис, отдают ответ.

**Где находятся правила создания и отмены брони.** Бизнес-правила создания брони живут в `BookingService`. Проверки формата отдельных полей (не пусто, положительное число) — на DTO через ограничения `#[Assert]`, они срабатывают автоматически при маппинге запроса. Контроллер правил не содержит.

**Кто отвечает за проверку пересечения интервалов.** `BookingService` через метод `BookingRepository::findOverlapping`. Это DQL-запрос, отбирающий действующие брони комнаты, где `startAt < :end` и `endAt > :start`. Строгие неравенства дают нужное поведение: касание границ разрешено. Фильтр по статусу `active` гарантирует, что отменённые брони время не блокируют.

**Как представлено состояние брони.** PHP-enum `BookingStatus` со значениями `Active` и `Cancelled` (строковый backed-enum). В базе хранится строкой, при создании брони статус по умолчанию — `Active`. Статус доступен вызывающему коду и попадает в JSON-ответ.

**Как вызывающий код узнаёт о нарушении бизнес-правила.** Через доменные исключения (`RoomNotFoundException`, `InvalidBookingPeriodException`, `CapacityExceededException`, `BookingConflictException`, `EquipmentNotFoundException`). Каждое помечено атрибутом `#[WithHttpStatus]`, поэтому Symfony автоматически превращает его в HTTP-ответ с нужным кодом (400/404/409) и сообщением. Ошибки формата входных данных валидатор возвращает как `422`. Успех и ошибка различимы по HTTP-коду.

**Какие зависимости между частями.** Однонаправленные: контроллер → сервис → репозитории и `EntityManager`. Все зависимости внедряются через конструктор (автовайринг Symfony). Сущности самодостаточны и ни от чего не зависят.

**Недостатки и спорные места.** Организатор представлен просто строкой-идентификатором, без сущности пользователя. Нет автотестов. Не реализованы отмена и расписание. `findOverlapping` возвращает массив, хотя для проверки достаточно `exists`/`count`. В dev-окружении ошибки отдаются со стеком (в prod этого не будет).

**Что улучшил бы, имея ещё 4 часа.** Реализовал бы отмену брони и получение расписания, покрыл бы логику тестами (в первую очередь проверку пересечения), добавил бы группы сериализации для аккуратного вывода и подумал бы над валидацией входных дат.

## Краткий отчёт о работе

- **Фактически потрачено времени:** около 5 часов
- **Что успел реализовать:** создание комнаты с оборудованием и валидацией; создание брони со всеми правилами (существование комнаты, корректность периода, вместимость, проверка пересечения); единообразная обработка ошибок через доменные исключения.
- **Что не успел:** отмену брони, получение расписания комнаты, автотесты.
- **Самая сложная часть:** Работа с фреймворком Symfony, ORM Doctrine, работа с репозиториями.
- **Решение, в котором сомневаюсь:** сомневаюсь в [BookingService.php](src/Service/BookingService.php) а именно в приватных методах.
